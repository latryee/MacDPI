# MacDPI 0.3.0 personal TUN report

The free personal build is implemented and packaged as version 0.3.0/build 8. The final source passed every GitHub CI job: Intel and Apple Silicon isolated checks/builds, plus 29 hosted model/process and three native UI cases on macOS 27. Build 8 fixes selectable diagnostics accessibility; its final app/ZIP/DMG and three packaged absent-broker cancellation checks passed. Manual inspection of the promoted app confirmed Disabled and a current diagnostics report without activation. Networking implementation is unchanged from build 7, whose approved physical sleep/wake and graceful shutdown trial passed. Build 6 remains the owner-confirmed Discord two-way voice, real Roblox gameplay and rejoining record. This is a personal testing preview with the runtime limits below. [Current proof](verification/0.3.0-release-readiness.json), [CI](https://github.com/latryee/MacDPI/actions/runs/42500004385).

In the earlier build 3 evening trial, the late independent snapshot encountered a **new owner-started session**. It therefore could not reproduce that disabled baseline for interfaces/capture policy. DNS, proxies, physical defaults, primary service and service order still matched. The old trial's engine/helper were gone. The new session survived a window close/reopen with the same engine/helper and was left enabled by the owner; the agent's monitor stopped. That historical snapshot does not prove full restoration. The subsequent build 6 trial independently verified all eight categories after Disable.

The normal application has no ten- or thirty-minute active-session timer. Those limits belonged to the authorized development trials, which the operator ended with Disable. Automatic setup cannot guarantee all sites or overcome encrypted/absent server names, every resolver policy or UDP-specific blocking. Extended daily reliability is still unverified. Remote GitHub CI now passes; optional Developer ID signing/notarization is not completed. The prepared public distribution remains an ad hoc personal testing preview.

The root helper is excluded and disclosed, and no background resource polling is added. TCP/UDP/DNS algorithms are unchanged, while startup/cancellation and detach-verification lifecycle handling changed. A later approved build 6 activation and monitored interval passed with verified restoration. It was not an exact 30-minute Active test. The earlier [resource UI record](verification/0.3.0-resource-ui.json) is historical; [historical build 6 hashes and checks](verification/0.3.0-build6-release.json) preserve that evidence. The prior [0.2.0 engineering report](FINAL_REPORT.md), build artifacts and local proxy path remain available. No Gatekeeper/SIP weakening, trust installation or system DNS/proxy/VPN rewrite is part of this workflow.

The late stop was observed only after it happened. Later protected-prefix hashes differ, which is consistent with one guard condition but does not prove causality. Neither root journal contents nor a retained reason establish why it stopped. Build 5 corrects the UI's overly specific helper attribution without pretending to fix that unknown trigger. [Late-stop record](verification/0.3.0-late-stop.json).

Build 6 writes only fixed caught-failure categories to the local macOS unified log. Worker logging is gated by the final failed outcome; normal stop/cancel is excluded. The helper startup branch accepts stop before readiness as cancellation, but this branch was compiled rather than directly executed with a real TUN. Known-lease detach verification has a local regression; native IPC tests cover the transport/release model, not a live helper startup. These changes and diagnostics do not retrospectively identify or fix the unexplained build 3 stop. A later manual read-only build 6 GUI check observed Disabled, Enable available, the inactive resource card with helper-excluded scope, Automatic setup selected and launch at login unchecked.
