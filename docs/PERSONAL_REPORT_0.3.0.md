# MacDPI 0.3.0 personal TUN report

The free personal build is implemented and packaged. On the development Mac/network, the owner confirmed bidirectional Discord audio and entering and remaining in a Roblox game while Automatic setup was enabled. Public HTTPS, the Discord API and an unauthenticated Gateway WebSocket were independently checked over the physical TUN path. This is a successful personal trial, with the broader validation limits below. [Detailed timeline](TUN_VERIFICATION.md), [sanitized live evidence](verification/0.3.0-live-personal.json).

| Required report item | Result and evidence |
| --- | --- |
| 1. Implementation | Native SwiftUI/AppKit host, independent local proxy, personal packet engine, bounded TCP/UDP, DNS, TLS record splitting, route journal, recovery, menu controls and release tooling. The 0.2.0 source/build and optional extensions are preserved separately. |
| 2. Architecture | Native Darwin `utun` descriptor shared with an unprivileged Swift/Go worker. Pinned gVisor reconstructs TCP streams and UDP datagrams. Each physical dial is interface-bound to avoid recursion. The previous Swift TLS/DNS logic is reused. No external DPI executable or remote relay is required. [Design](../ARCHITECTURE.md). |
| 3. Paid membership | Avoided for this personal build through ad hoc signing and kernel-control authorization. No Network Extension profile is required or activated. Developer ID signing/notarization is not claimed. |
| 4. Administrator privileges | Only the session helper configures the new interface, journals/adds capture routes and verifies release. UI, DNS/TLS processing and all TCP/UDP forwarding stay unprivileged. No setuid binary, password storage, sudoers change or persistent daemon. |
| 5. Enable | Starts the worker, verifies signed components and asks macOS for authorization through `osascript`. Bounded copies are read as the requesting user into private root staging and checked against hashes embedded in the host. The helper authenticates the worker's UID and live audit-token code hash. Active requires actual route readiness. |
| 6. Disable | Stops packet work, releases the descriptor copies, and asks the broker to verify that its interface/routes are gone. It removes no unrelated route. The latest trial visibly reached Disabled and its old processes exited. The earlier GUI trial independently matched all eight baseline policy fingerprints. |
| 7. Engine failure | EOF/lease loss stops the other component. The worker releases its duplicate on helper loss. The known-lease detach regression is locally tested, including absent ownership/journal state. Native IPC tests cover transport and cleanup acknowledgements. The helper stop-before-readiness branch was compiled, not directly exercised with a real TUN. Actual startup cancellation and forced-termination validation remain pending. Unconfirmed cleanup becomes Recovery required. |
| 8. Network preservation | Original defaults, DNS, proxies, VPNs and service ordering remain as found. Only a bounded public-prefix cover on the session's own interface is added. Private/protected networks are excluded. Changes from another app are not overwritten. [Ownership and recovery](TUN_ROUTE_SAFETY.md). |
| 9. TCP | Synthetic IPv4/IPv6 integrity, half-close, server-first and first-flight transformation passed. The mixed fixture verified 58.56 MiB each direction per family. Real certificate-verified public HTTPS/API/WSS passed. Physical throughput and IPv6 remain unmeasured. |
| 10. UDP | IPv4/IPv6 empty, fragmented and maximum-datagram fixtures passed. Loss fixtures received 72 replies with exactly eight injected drops per family. Concurrent load received all 2,996 UDP replies per family. No UDP/QUIC transformation or general filtering bypass is claimed. |
| 11. DNS | System DNS is retained for ordinary traffic. Captured eligible DNS can use validated DoH. Automatic selective origin repair validates the visible service name and public same-family encrypted answer. Split/local names keep their path; explicit encrypted failure does not downgrade. Cache bounds, expiry, coalescing and invalid-answer checks are tested. [Privacy](../PRIVACY.md). |
| 12. Discord desktop | Owner reported correct operation while enabled. Public API and unauthenticated WSS were separately verified. Login and messaging substeps were not independently observed or timed; no authenticated session was inspected. |
| 13. Discord voice | Owner explicitly confirmed both participants could hear one another. Voice RTT, loss, duration, reconnect and different networks/regions were not quantified. |
| 14. Roblox gameplay | Owner confirmed entering a real game and remaining connected. Exact duration, game identity, authentication sequence, reconnect and gameplay RTT were not collected. |
| 15. CPU/RAM | A 496.17 s enabled sample averaged 0.411% combined CPU and peaked at 130.33 MiB RSS across host/engine/helper. User traffic was uncontrolled. Strict idle, battery and 30-minute stability are unverified. [Measurements](../PERFORMANCE.md). |
| 16. Builds/tests | Build 6 built app/helper/engine as Universal 2, version 0.3.0. It passed 130 Swift core, 27 hosted model and 14 packaging cases. The current Debug CLI freshly passed 23 loopback scenarios; four native TCP/UDP IPv4/IPv6 scenarios also passed. The full Go suite, 15-second mixed runs per family, synthetic IPv4 96-TCP/64-UDP capacity, UDP idle/activity/cancellation, targeted UDP lifecycle race and native IPC checks passed. Three native UI cases are a prior run; the current interactive check was unavailable because the Mac was locked. The owner-participated live trial used build 3. [Tests and scope](TUN_VERIFICATION.md). |

| 18. Packaging | Build 6 app, ZIP, DMG and SHA-256 are under `build/personal/release` and `build/personal/dist`. Ad hoc signatures, nested components, both slices, exact extracted archives and post-promotion checksums were verified. Bundled Go/gVisor dependency notices are included. No GitHub publication occurred. [Current proof](verification/0.3.0-release-readiness.json). |
| 19. Approval-dependent validation | Thirty-minute stability, deliberate engine/helper crash, sleep/wake and network/VPN switching need separate test scopes and approval. Other hardware/OS runtime needs an appropriate machine. None was silently treated as passed. |
| 20. Safe real-world steps | Use the verified personal app, keep Automatic setup, press Enable and approve macOS. The user handles account login, microphone and game/voice interactions. Test ordinary access, two-way audio and a real game separately. Press Disable, wait for verified release and compare connectivity/settings. An uncertain result requires recovery review, not blanket network reset. [Procedure](PERSONAL_TUN.md#first-authorized-test). |

The late independent snapshot from the longer trial encountered a **new owner-started session**. It therefore could not reproduce the disabled baseline for interfaces/capture policy. DNS, proxies, physical defaults, primary service and service order still matched. The old trial's engine/helper were gone. The new session survived a window close/reopen with the same engine/helper and was left enabled by the owner; the agent's monitor stopped. Full eight-fingerprint restoration is supported by the earlier short GUI test, not by that late snapshot.

The normal application has no ten-minute session timer. That limit belonged to the authorized development trial. Automatic setup cannot guarantee all sites or overcome encrypted/absent server names, every resolver policy or UDP-specific blocking. Extended daily reliability is still unverified. Signing/notarization and remote GitHub workflow execution are not complete; the repository and manual preparation workflow are ready for review, without an automatic publish step.

Build 6 retains the bounded, on-demand CPU/RSS display for the app and engine. It shows unavailable values when accounting fails and rejects results from a changed or stopped session. The root helper is excluded and disclosed, and no background resource polling is added. TCP/UDP/DNS algorithms are unchanged, while startup/cancellation and detach-verification lifecycle handling changed. No live build 6 activation or 30-minute test was performed. The earlier [resource UI record](verification/0.3.0-resource-ui.json) is historical; [current hashes and checks](verification/0.3.0-release-readiness.json) cover build 6.

The prior [0.2.0 engineering report](FINAL_REPORT.md), build artifacts and local proxy path remain available. The MIT project includes separately licensed pinned Go/gVisor code in the personal worker; notices ship with the app. Build from reviewed source if macOS declines a downloaded ad hoc artifact. No Gatekeeper/SIP weakening, trust installation or system DNS/proxy/VPN rewrite is part of this workflow.

The late stop was observed only after it happened. Later protected-prefix hashes differ, which is consistent with one guard condition but does not prove causality. Neither root journal contents nor a retained reason establish why it stopped. Build 5 corrects the UI's overly specific helper attribution without pretending to fix that unknown trigger. [Late-stop record](verification/0.3.0-late-stop.json).

Build 6 writes only fixed caught-failure categories to the local macOS unified log. Worker logging is gated by the final failed outcome; normal stop/cancel is excluded. The helper startup branch accepts stop before readiness as cancellation, but this branch was compiled rather than directly executed with a real TUN. Known-lease detach verification has a local regression; native IPC tests cover the transport/release model, not a live helper startup. These changes and diagnostics do not retrospectively identify or fix the unexplained build 3 stop. The current interactive UI check was unavailable while the Mac was locked.
