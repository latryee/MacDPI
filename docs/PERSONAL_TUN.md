# MacDPI 0.3.0 personal TUN preview

This build packages a separate unprivileged UI and data engine plus a short-lived administrator helper. It uses no Developer ID or Network Extension profiles and includes neither of the previous system extensions. It is ad hoc signed. The minimum macOS target is 12.0. Building from reviewed source is the supported path if macOS declines a downloaded ad hoc bundle.

## Build and safe checks

```sh
scripts/fetch-tun-toolchain.sh
scripts/test-tun-worker.sh
scripts/test-tun-ipc.sh
scripts/test-tun-route-snapshot.sh
swift test --scratch-path build/swift
MACDPI_PERSONAL_TUN=1 MACDPI_BUILD_ROOT=build/personal scripts/package-release.sh --dmg
```

Full Xcode, Python 3 and the pinned Go compiler are build tools. The explicit fetch script checks the published SHA-256 of the Go 1.26.10 archive. The worker build checks pinned Go modules against `go.sum` and links the gVisor network stack into the bundled engine. It applies a narrowly scoped, source-hash-checked fix to account for receive queue metadata even when a UDP datagram is empty. The original module stays untouched. Go, gVisor and transitive dependency notices are bundled in `Contents/Resources/TUNLicenses`. The running application requires no Go installation or separate DPI tool. [Go archive checksums](https://go.dev/dl/), [pinned gVisor source](https://github.com/google/gvisor/tree/479e1cc2c3d9), [reviewed dependency patch](../Tools/TUNWorker/prepare-dependency.py).

## Why this design

The helper connects to the macOS `utun` kernel control, configures only the new interface, and passes its packet descriptor to the engine over a one-session Unix socket. The kernel control requires root. It is separate from Apple's Network Extension authorization. SpoofDPI provided a reference for `utun`, the packet framing and physical-interface binding. Its referenced stack enables only IPv4. MacDPI enables both IPv4 and IPv6 in its packet stack and captures a family only when the Mac has a validated physical default for it. [Apple XNU utun source](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/net/if_utun.c), [SpoofDPI macOS backend](https://github.com/xvzc/spoofdpi/blob/v1.5.5/internal/server/tun/tun_net_darwin.go), [SpoofDPI stack](https://github.com/xvzc/spoofdpi/blob/v1.5.5/internal/server/tun/tun.go).

The preview asks the user to run a fixed Terminal command for each session. This makes the administrator action visible and avoids depending on ad hoc Service Management registration or a persistent root daemon. The helper authenticates the selected user and verifies the live engine's code hash using the socket's audit token. The engine verifies that the broker peer is root. Neither the application nor helper collects an administrator password. A disposable helper process owns the interface and a locked recovery journal. [Apple DTS on Service Management and ad hoc signatures](https://developer.apple.com/forums/thread/799910), [route ownership and recovery](TUN_ROUTE_SAFETY.md).

The unprivileged engine reconstructs TCP streams and UDP datagrams with gVisor and dials original numeric destinations on the captured physical interface. It never retries an unbound dial. TCP 443, 8443 and 9443 can use the existing Swift ClientHello transformation. Compatibility passes through the original record. The split preserves handshake data and end-to-end TLS validation. The transport stack handles TCP sequencing and IPv4/IPv6 IP reassembly. The data path has 96 TCP and 64 UDP flow slots, a 128-packet output queue, bounded TCP buffers and 128 KiB UDP receive budgets that also charge for empty packets. UDP payloads are forwarded without a DPI transformation.

System DNS keeps the current resolver path. The Cloudflare option uses certificate-verified HTTPS only for eligible **captured** TCP or UDP DNS queries on port 53. A private resolver outside the capture routes stays outside the tunnel. System search domains, split domains and local names stay with the original resolver. Encrypted exchange failures produce a validated DNS error instead of a plaintext retry. The DNS bridge checks the response question and transaction and handles EDNS UDP truncation. Cloudflare replies with private or special-use A, AAAA or SVCB/HTTPS address hints receive SERVFAIL. Original split-DNS replies retain their private answers. TUN mode leaves caching to the clients and resolvers. It does not flush or rewrite system DNS state. The local proxy retains its previous DoH cache. [SVCB and HTTPS address hints](https://www.rfc-editor.org/rfc/rfc9460.html#section-7.3).

The development Mac's read-only snapshot showed a single private or special-use resolver and zero public resolver addresses. On that setup the Cloudflare option will not replace the system resolver. Direct Discord requests with that system resolver failed certificate verification even though ordinary HTTPS worked. Changing the active network service's DNS or adding a temporary DNS profile is a separate, reversible experiment. It needs its own recorded baseline and approval. macOS exposes session-owned Dynamic Store values, but an all-domain resolver override would still need verification of resolver priority, failure behavior and split-DNS preservation. The helper leaves DNS settings as found. [Apple Dynamic Store API](https://developer.apple.com/documentation/systemconfiguration/scdynamicstore-gb2), [Apple resolver selection source](https://github.com/apple-oss-distributions/configd/blob/main/Plugins/IPMonitor/dns-configuration.c).

With Standard or Advanced and Cloudflare selected, the optional **Repair suspected Discord and Roblox DNS answers for TLS** toggle can recover some TCP 443 connections on this setup. It compares two fixed System DNS names for each service at startup. A shared singleton public address triggers inspection of the first TLS record only for connections to that address. For an eligible visible service name, Cloudflare's verified A or AAAA answer can supply the destination on the same address family. A failed encrypted lookup ends that connection. Unmatched names and split DNS preserve the original address. Client TLS validation stays end-to-end. The option leaves system DNS, UDP and QUIC alone and cannot recover a flow with no eligible visible name or a destination outside the route cover.

## First authorized test

For a short transport and cleanup check, run `python3 scripts/test-tun-live.py --approved` in Terminal after reviewing the scope below and authorizing the temporary interface and routes. This script uses the locally built personal bundle under `build/personal/release`. It checks ordinary HTTPS before, during and after one session, then compares the eight policy fingerprints. It runs the packaged worker and helper directly and ends the session automatically. The app and service trials below exercise the rest of the workflow.

Add `--discord` only when the trial also authorizes requests to Cloudflare DoH and Discord's public gateway API. The script obtains one public IPv4 address over DoH before activation and compares the same certificate-verified API request before, during and after the tunnel. It compares System DNS with the pinned address and verifies that the pinned address moved into the tunnel and back to its original interface. No DNS settings are changed. The test helps distinguish resolver interference from failure on the captured TLS path. Desktop login and voice require the manual trial below.

For an authorized comparison of the optional repair, use `python3 scripts/test-tun-live.py --approved --discord --repair-origin` when direct System DNS fails for the Discord API. The script selects Standard, Cloudflare and TLS origin repair, then checks both the pinned and ordinary public gateway requests during the temporary session.

1. Use a locally verified build. Review its signature and archive checksums. Choose a test window with a Terminal window open and a known working connection. Confirm that active VPNs, other packet interceptors and Internet Sharing are outside the trial scope. The helper refuses detected conflicting routes and IP forwarding. Some OS filters do not expose their state in the route table.
2. Run `scripts/test-tun-route-snapshot.sh` to check the physical path and estimated route count. In the same Terminal session, run `before=$(scripts/test-tun-route-snapshot.sh --fingerprint)` to capture a local baseline. The command prints only hashes for the primary service, physical defaults, interfaces, protected prefixes, DNS, proxies, service order and network policy. Establish that normal browsing and LAN connectivity work before the trial. Leave **System DNS** selected for the first check.
3. Open the personal bundle and press **Enable**. Review and copy the exact displayed command. It invokes the bundled `MacDPITUNHelper run <session UUID>` through `/usr/bin/sudo`. Run it in Terminal yourself only after authorizing this test. Leave Terminal open. If an authorized helper cannot connect within 90 seconds, press **Enable** again and use the new command. The helper will create its new interface, check engine readiness, journal its route plan, add only eligible public prefixes and verify scoped physical egress. A green status requires the helper's activation acknowledgement.
4. Verify ordinary web access and an unaffected local endpoint. Then test new Discord and Roblox sessions with the user's participation. Separate **Discord** launch, user login, messaging, gateway persistence, reconnection, voice signaling and two-way audio. Separate **Roblox** website, user login, native launch, game join, sustained play and reconnect. The user handles authentication, microphone and game/voice interactions. Compare Compatibility and Standard on the same network only when authorized.
5. Press **Disable**, let the helper verify interface and route release, then check ordinary connections again. If the helper exits while enabled, the worker observes the lost lease and closes its duplicate. If the worker exits, the helper rolls back on EOF. An unconfirmed result displays **Recovery required**. Run the bundled helper's `recover` command from the app or Terminal, with explicit approval. This audits the journal and detached interface. It never runs a generic route deletion. If it cannot confirm the recorded state is gone, leave the tunnel disabled and inspect before retrying. [Recovery details](TUN_ROUTE_SAFETY.md).
6. After a successful bounded trial, separately approve trials for interface changes, sleep/wake, crash and long-run performance. The current watchdog checks path and route changes on a bounded interval. Physical changes should stop the session for reauthorization. Abrupt termination and restart still need real Mac validation.

Quit the app after the helper has completed its rollback attempt. The window can be closed while an explicitly enabled session runs. Once the helper has exited and recovery is clean, uninstall by deleting the app. The helper creates no daemon or login item. It can leave its private, root-owned lock directory. Its documented recovery command audits any recorded route lease before a new start.

After Disable, run `after=$(scripts/test-tun-route-snapshot.sh --fingerprint)` and `diff -u <(printf '%s\n' "$before") <(printf '%s\n' "$after")` in that same Bash or Zsh session. An empty diff shows that the sampled settings and route policy match. A difference can also come from an unrelated network change. Inspect it without overwriting the current settings. The fingerprint comparison supplements the helper's lease-specific cleanup check and the manual connectivity test.

## Evidence boundary

The host, helper and engine compile for arm64 and x86_64. On Apple Silicon, isolated tests cover TCP integrity and half-close, IPv4 and IPv6 UDP boundaries including empty and fragmented messages, DNS failure, route ownership and crash simulations, and native IPC. A user-authorized smoke test verified real IPv4 activation, ordinary HTTPS and interface detach with the packaged binaries. The app's installed Enable/Disable path and native Discord and Roblox still need real sessions. The preview has no enabled-path CPU, RAM or battery measurements yet. [Engineering report](TUN_VERIFICATION.md).
