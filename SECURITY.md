# Security policy and review

The 0.3.0 personal preview packages a separate data engine and a short-lived route helper. The UI and engine run as the user. Enable requests macOS administrator authorization through Apple's `osascript`; credentials stay with macOS. The launcher copies components as the requesting user into a root-only directory and checks hashes embedded in the running host before executing the helper. The helper verifies the worker's UID and live audit-token code hash; the worker requires a root broker peer. The personal build omits App Sandbox for local descriptor IPC and carries no privileged signing entitlement, setuid executable or persistent daemon. Ad hoc signatures check bundle integrity but provide no distribution identity. Authorize only a bundle built from reviewed source or otherwise trusted. [Personal TUN authorization and recovery](docs/PERSONAL_TUN.md), [route ownership and rollback](docs/TUN_ROUTE_SAFETY.md).

The personal build has source, isolated and owner-approved real TUN evidence on one Mac. The following provider-specific review concerns the preserved optional Network Extension path; its installed operation and cross-product filtering behavior still require validation. After publication, use the repository's private vulnerability reporting channel when available. Avoid sharing credentials or captured traffic in public issues.

- **Local access.** The app binds only to IPv4 loopback. It generates a random per-launch credential, validates CONNECT requests and checks authentication before any DNS or outbound connection. Duplicate credentials, request bodies and transfer encoding are rejected. The headless CLI is an unauthenticated loopback test utility and is excluded from the app bundle. A local process can still compete for a bounded listener slot. Explicit clipboard copies can expose the current credential to other local clipboard readers.
- **Outbound target.** The local proxy validates resolved addresses, pins the permitted numeric result and connects directly. Transparent forwarding uses the OS-provided public numeric endpoint. Private, loopback and unsupported endpoints remain outside production admission. The provider excludes its own identities, and TCP/DNS re-injection, actual OS flow ordering and coexistence with VPNs require on-device checks.
- **Forwarding.** TCP rewrites only the framing of a complete first ClientHello record. TLS handshake bytes remain intact, with origin authentication performed by the client. UDP preserves payloads. A transparent flow that the provider declines may go through normal routing. Treat the app as a traffic utility with no kill-switch guarantee.
- **DNS.** DoH uses normal HTTPS validation and a numeric bootstrap address. The response must match the request's transaction ID and question. Split domains and bound interface flows use their original resolver intentionally. DNS provider answers preserve records and DNSSEC metadata but the provider does not validate DNSSEC independently. Local CONNECT still rejects private resolved addresses even if a resolver returns them.
- **Lifecycle and resources.** Signed capability checks precede OS changes. The app uses its own preference identifiers, bounded flow admission, read/send backpressure, deadlines and generation checks. Provider readiness requires a fresh reply. The DNS control service validates the exact expected signing team and identifier on each message. The ad hoc host cannot activate the providers. Installed rollback and authenticated IPC remain unverified.
- **Distribution.** Production requires Developer ID Application signing, valid matching profiles, Hardened Runtime, secure timestamps and notarization. The local packages use ad hoc signatures. Keep profiles and credentials outside source control. Use ordinary macOS approval and Gatekeeper checks.

The personal worker statically includes pinned Go/gVisor dependencies and bundled license notices; no separate runtime installation is needed. The optional Swift modes use Apple SDK frameworks. Tests use generated temporary loopback certificate material. Ordinary CI performs no privileged networking, authenticated application checks, trust changes or extension activation.
